# Deck=8 first-selection causal reach/leverage experiment

## Question

The production deck=8 chance panel is attached to the action which completes
the current round and reveals the next row.  From the first selection of that
round, this action is four game actions below the root.  A panel can affect the
root only if search reaches that action and then has enough simulations left to
revisit the affected branch and propagate the changed estimate upward.

This experiment separates three possible failure modes:

1. **Reach:** ordinary search does not reach the reveal action often or early
   enough.
2. **Leverage:** it reaches the action, but even an unrealistically strong and
   free value intervention cannot materially change root allocation.
3. **Estimator/cost:** a free intervention has leverage, but a real 70-row
   panel is too weak or displaces too much ordinary search.

This is a diagnostic experiment only.  It does not enable chance correction in
self-play.

## Frozen positions

The preregistered set contains 64 independent `PLACE_AND_SELECT` roots with:

- `deck == 8`;
- `actor_index == 0` (the first tile selection of the round);
- one root per independently seeded game;
- no chance-correct treatment during trajectory generation.

Positions are generated by the existing greedy current-checkpoint AZ-MCTS
trajectory helper at 32 simulations per move.  The checkpoint hash, game seed,
trajectory ply, and generation settings are embedded in the frozen JSONL or
experiment provenance.  The set is immutable once the full sweep starts.

Decision: use 64 independent games rather than repeatedly sampling a few
trajectories.  The experiment's uncertainty is dominated by position-to-
position variation, so independent roots are more valuable than multiple
search seeds on the same small set for this first pass.

## Arms and budgets

Every position uses common random numbers across arms at configured budgets
`800, 1600, 3200, 6400`.

| Arm | Ordinary paths | Panel rows | Purpose |
|---|---:|---:|---|
| `control` | B | 0 | incumbent reach/depth curve |
| `pulse_positive` | B | 0 | clamp first reached reveal action Q to +1 in root-actor frame |
| `pulse_negative` | B | 0 | clamp the same kind of action Q to -1 |
| `panel_charged` | B−70 if admitted; otherwise B | 70 if admitted | production-like equal-work treatment |
| `panel_extra` | B | 70 if admitted | isolate panel information from compute displacement |

The pulse is persistent after admission: ordinary backups may visit the target,
but its Q is reset at every parallel-wave boundary.  It adds no evaluator rows.
This is intentionally a maximum-leverage intervention, not a proposed search
algorithm.

The charged arm reserves 70 work units atomically only when the panel is
actually admitted.  If the first reveal is never reached, or it is reached too
late for the complete panel to fit, the arm retains all B ordinary paths.  This
matches the production reservation rule and avoids charging an intervention
which never happened.

The real panel evaluates all `C(8,4) = 70` public rows, including the row from
the triggering sampled path.  That deliberate duplicate matches the production
batch exactly; generic A1c widening normally reuses an already-estimated row.

## Recorded diagnostics

For every arm, position, and budget the resumable artifact records:

- first reveal-reach simulation and one-based game-action depth;
- count and fraction of paths crossing a reveal action;
- unique reveal nodes and root branches which reached one;
- maximum and mean decision depth;
- target root action, visits at intervention, final visits, and post-admission
  visits;
- simulations remaining after the intervention was applied;
- panel requested/committed state and exact bootstrap-row count;
- ordinary simulations, realized work units, NN rows, evaluator calls, and
  wall time;
- complete root visit shares, Q values, priors, top action, and top pick.

The Python wrapper independently counts evaluator rows and fails if its count
differs from Rust's accounting.

## Preregistered interpretation

The primary analysis is paired by frozen position and reported separately at
each budget.  Reach rates and top-action change rates use Wilson 95% intervals;
continuous paired effects use a deterministic position bootstrap.

A root-policy change is considered material descriptively when either the top
action changes or total variation distance between root visit distributions is
at least 0.10.  This threshold is an interpretation aid, not a promotion gate.

- **Reach bottleneck:** reveal reach remains uncommon at 3,200/6,400, or most
  admissions leave little remaining search.  In this case a correct value at
  the deep chance node cannot reliably influence the first selection under the
  current tree shape.
- **Leverage bottleneck:** reveal nodes are reached with substantial remaining
  search, but the ±1 pulses rarely cause material root-policy changes.  A real
  estimator cannot overcome this because the pulses bound its plausible
  influence.
- **Estimator bottleneck:** pulses are material but `panel_extra` is not.  The
  70-row network bootstrap is not changing the targeted value enough, even when
  compute displacement is removed.
- **Compute-displacement bottleneck:** `panel_extra` is material while
  `panel_charged` is not.  The panel has useful information, but spending 70
  ordinary paths erases the benefit.
- **Promising mechanism:** both pulse and real-panel arms increasingly affect
  root allocation with budget, and the charged arm approaches the extra-budget
  arm.  Only this outcome justifies a subsequent playing-strength A/B test.

No result from this diagnostic alone enables the feature or changes self-play.

## Reproduction

From the repository root, using the project virtual environment and CUDA:

```powershell
.\.venv\Scripts\python.exe -m games.kingdomino.chance_leverage_probe --mode freeze
.\.venv\Scripts\python.exe -m games.kingdomino.chance_leverage_probe --mode run
```

For a one-position, one-budget smoke run, use a separate output file so its
provenance cannot collide with the full artifact:

```powershell
.\.venv\Scripts\python.exe -m games.kingdomino.chance_leverage_probe --mode run `
  --limit 1 --budgets 800 `
  --output runs/kingdomino/chance_correct_a1/deck8_causal_leverage_smoke.json
```

Default outputs:

- positions: `runs/kingdomino/chance_correct_a1/deck8_first_selection_positions_v1.jsonl`
- results: `runs/kingdomino/chance_correct_a1/deck8_causal_leverage_v1.json`

The results file is atomically rewritten after every completed arm.  Re-running
the same command resumes missing cells and refuses to mix differing provenance.

## Verification gates

The focused tests prove:

- `control` is exactly the existing exposure-zero advisor path;
- a reached first reveal is reported at game-action depth four;
- pulses add no NN work;
- the real panel commits 70 rows exactly once and creates no fake visits;
- charged admission realizes exactly B work units;
- invalid root shapes and modes fail loudly.

The surrounding A1/A1c and production panel regression suites are also run
before the experiment.
